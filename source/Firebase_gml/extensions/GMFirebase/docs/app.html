App¶

This module covers the Firebase App every other module attaches to, the synchronous error channel, the SDK's log level and the conventions the whole extension follows.

Initialisation¶

Call firebase_app_initialize once, before any other function of this extension or of the GMFirebaseCrashlytics, GMFirebasePerformance and GMFirebaseInAppMessaging extensions. It reads the credential file the extension options point at (see Getting Started and Extension Options) and creates the default app. Each product module then has its own initialize function - firebase_analytics_initialize, firebase_messaging_initialize and so on, or creates itself on first use as firebase_auth_get_auth does - which attaches that product to the default app. The *_for_app variants attach it to a second app instead, created with firebase_app_initialize_with_options or firebase_app_initialize_from_json.

Errors and callbacks¶

Every function that takes a callback returns FirebaseError synchronously. FirebaseError.Ok means the call reached the SDK and the callback will be called exactly once, on the game's own thread, with the SDK's result: an error_code argument (0 on success, otherwise the product's own error enum - FirebaseAuthError, FirestoreError, FirebaseDatabaseError, FirebaseRemoteConfigError - or the SDK's raw code where no enum is declared), an error_message string, and then the value the call produces, if any. Any other return means the call failed before the SDK saw it, the callback will never be called, and firebase_last_error_code and firebase_last_error_message hold the reason.

Warning

FirebaseError.Ok is 0. Compare the return against FirebaseError.Ok; a truthy test (if (firebase_..._(...))) runs its body on failure. The only functions of this extension that return a plain success flag are the initialize family - firebase_app_initialize, firebase_analytics_initialize and their siblings.

Handles¶

Firebase objects - apps, users, references, documents, queries, snapshots - reach GML as numeric handles. A function that returns one names the function that releases it, and 0 always means "no object". A handle can be released as soon as the call that needed it has started: the SDK holds what it needs, and the callback still fires. The one exception is a Cloud Storage reference on Windows, macOS and Linux, which must stay alive until the callback of any operation started on it has fired - see firebase_storage_ref_release. A handle that was released, or never valid, makes a call fail with FirebaseError.InvalidHandle.

firebase_app_initialize¶

Firebase C++ SDK: firebase::App::Create

This function creates the default Firebase App, or reuses it when one already exists, and must be called once before any other function of this extension. Every product module (Analytics, Authentication, Cloud Firestore, ...) attaches to the App this call creates.

Where the configuration comes from depends on the platform: on Android it is the google-services.json file that the jsonFile extension option stages into the build, on iOS the GoogleService-Info.plist that the plistFile option adds to the bundle, and on Windows, macOS and Linux a google-services-desktop.json or google-services.json placed beside the executable, which the desktopJsonFile option copies there at build time. See Extension Options.

If the function succeeds it returns true. If it fails it returns false and firebase_last_error_code is FirebaseError.NotInitialized, with firebase_last_error_message saying why - typically a configuration file that could not be found or read.

Note

This function returns a boolean, not a FirebaseError value, so a truthy test on its return is correct here. The asynchronous functions of this extension return FirebaseError instead, where FirebaseError.Ok is 0 - see the notes on this page.

Important

On iOS the GMFirebaseCrashlytics, GMFirebasePerformance and GMFirebaseInAppMessaging extensions depend on this call having configured the default app; their functions are no-ops until it has run. On Android the default app is configured at launch and those three work either way.


Syntax:

firebase_app_initialize()


Returns:

Boolean

true if the default app exists after the call, otherwise false.


Example:

if (!firebase_app_initialize())
{
    show_debug_message("Firebase init failed: " + firebase_last_error_message());
    exit;
}
show_debug_message("Firebase App: " + firebase_app_get_name());
The above code initialises Firebase in a Create event and stops if that fails, printing the reason from firebase_last_error_message. Once it has succeeded, firebase_app_get_name returns the name of the default app and every other module can be initialised.

firebase_app_is_initialized¶

This function returns whether firebase_app_initialize has succeeded. It only reads the state; it never creates the app.


Syntax:

firebase_app_is_initialized()


Returns:

Boolean

true once the default app has been created, otherwise false.


Example:

if (!firebase_app_is_initialized())
{
    firebase_app_initialize();
}
The above code initialises Firebase only when it has not been initialised yet, which is the pattern for an object that can be created more than once during the game.

firebase_app_get_name¶

Firebase C++ SDK: firebase::App::name

This function returns the name of the default Firebase App. The SDK gives the default app a fixed name; an app created with firebase_app_initialize_with_options or firebase_app_initialize_from_json and a name of your own is read with firebase_app_handle_get_name instead.


Syntax:

firebase_app_get_name()


Returns:

String

The name of the default app, or an empty string when it has not been initialised.


Example:

show_debug_message("Firebase App: " + firebase_app_get_name());
The above code prints the name of the default app after firebase_app_initialize has succeeded.

firebase_last_error_code¶

This function returns the error code of the last call that failed before it reached the Firebase SDK - an invalid handle, a module that has not been initialised, or an argument the extension refused. The value is set on the thread that made the call, so read it right after a call has reported failure: after an asynchronous function returned anything other than FirebaseError.Ok, or after an initialise function returned 0.

Note that the value is not cleared by a later call that succeeds; it holds the code of the last failure until the next one overwrites it. Do not poll it to find out whether a call worked - the call's own return value says that.

A result the SDK produces - a sign-in that was rejected, a document that does not exist, a network error - never lands here. It is delivered to that call's callback, as the callback's error_code and error_message arguments, and nowhere else.


Syntax:

firebase_last_error_code()


Returns:

FirebaseError

The code of the last call that failed before reaching the SDK.


Example:

var _result = firebase_auth_sign_in_with_email_and_password(email, password, function(_error_code, _error_message, _user)
{
    // The SDK's own result arrives here
});

if (_result != FirebaseError.Ok)
{
    show_debug_message($"Sign-in not started: {firebase_last_error_code()} {firebase_last_error_message()}");
}
The above code starts a sign-in and checks the synchronous return against FirebaseError.Ok. When the call could not be started - here because firebase_app_initialize has not succeeded, so _result is FirebaseError.NotInitialized - the callback will never run, and firebase_last_error_code and firebase_last_error_message carry the reason. When the call did start, the callback is the only place the outcome is reported.

firebase_last_error_message¶

This function returns the message that goes with firebase_last_error_code - the name of the function that failed and what it objected to, for example "firebase_app_initialize: no google-services-desktop.json or google-services.json in <folder>". The same rules apply: it describes the last call that failed before reaching the SDK, it is not cleared by a later success, and an SDK result never lands here.


Syntax:

firebase_last_error_message()


Returns:

String

The message of the last call that failed before reaching the SDK, or an empty string when nothing has failed yet.


Example:

if (!firebase_app_initialize())
{
    show_debug_message("Firebase init failed: " + firebase_last_error_message());
}
The above code prints why the default app could not be created. The message names the missing or unreadable configuration file, which is the usual cause on desktop.

firebase_app_get_default_handle¶

Firebase C++ SDK: firebase::App::GetInstance

This function returns a handle to the default Firebase App, for the functions that take an app argument - firebase_analytics_initialize_for_app, firebase_messaging_initialize_for_app, firebase_app_check_get_instance_for_app and their siblings. On Windows, macOS, Linux and iOS the default app is created on demand if firebase_app_initialize has not run yet; on Android it must have run first, and the function returns 0 otherwise.

Release the handle with firebase_app_release_handle when you no longer need it. The app itself lives for the rest of the game; only the handle is released.


Syntax:

firebase_app_get_default_handle()


Returns:

Real

A handle to the default app, or 0 when it does not exist.


Example:

var _app = firebase_app_get_default_handle();
firebase_analytics_initialize_for_app(_app);
firebase_app_release_handle(_app);
The above code fetches a handle to the default app, initialises Analytics against it and releases the handle again, since the module keeps its own reference to the app from then on.

firebase_app_get_instance¶

Firebase C++ SDK: firebase::App::GetInstance

This function returns a handle to the app with the given name, created earlier with firebase_app_initialize_with_options or firebase_app_initialize_from_json. An empty name returns the default app. Unlike firebase_app_get_default_handle, this function never creates an app: it returns 0 when no app of that name exists.

Release the handle with firebase_app_release_handle when you no longer need it.


Syntax:

firebase_app_get_instance(name)
Argument Type Description
name String The name the app was created with, or an empty string for the default app.


Returns:

Real

A handle to the named app, or 0 when it does not exist.


Example:

var _app = firebase_app_get_instance("analytics-only");
if (_app == 0)
{
    _app = firebase_app_initialize_from_json(json_config, "analytics-only");
}
The above code looks up a named app and creates it from a configuration string when it does not exist yet, so the object that runs this can be created any number of times without creating the app twice.

firebase_app_get_apps¶

Firebase C++ SDK: firebase::App::GetApps

This function returns a handle to every Firebase App that exists, the default one included. Each handle should be released with firebase_app_release_handle when you are done with it.


Syntax:

firebase_app_get_apps()


Returns:

Array of Real

An array with one handle per app, empty when no app has been created.


Example:

var _apps = firebase_app_get_apps();
for (var _i = 0; _i < array_length(_apps); _i++)
{
    show_debug_message(firebase_app_handle_get_name(_apps[_i]));
    firebase_app_release_handle(_apps[_i]);
}
The above code prints the name of every app and releases each handle as it goes.

firebase_app_initialize_with_options¶

Firebase C++ SDK: firebase::App::Create

This function creates a Firebase App from the given FirebaseAppOptions instead of the configuration file, and returns a handle to it. Any variable of the struct left undefined keeps the SDK's default for that setting. With an empty name the app becomes the default app - the one every product module attaches to, exactly as if firebase_app_initialize had created it; with a name of your own it is a second app that only the *_for_app functions use.

If the SDK cannot create the app the function returns 0 and firebase_last_error_code is FirebaseError.NotInitialized.

Note

The usual way to configure the extension is the credential files described on Getting Started. Use this function when the configuration has to come from somewhere else at runtime - a second Firebase project, or values fetched from your own server.


Syntax:

firebase_app_initialize_with_options(options, name)
Argument Type Description
options FirebaseAppOptions The settings for the app; variables left undefined keep the SDK defaults.
name String The name for the app, or an empty string to create the default app.


Returns:

Real

A handle to the new app, or 0 when it could not be created.


Example:

var _options =
{
    app_id: "1:012345678901:android:0123456789abcdef",
    api_key: "AIza...",
    project_id: "my-second-project",
    messaging_sender_id: "012345678901"
};
second_app = firebase_app_initialize_with_options(_options, "second");
if (second_app == 0)
{
    show_debug_message(firebase_last_error_message());
}
The above code creates a second, named app for another Firebase project and keeps its handle in an instance variable so the *_for_app functions can use it later. The variables not given (database_url, storage_bucket, ga_tracking_id) keep their defaults.

firebase_app_initialize_from_json¶

Firebase C++ SDK: firebase::AppOptions::LoadFromJsonConfig

This function creates a Firebase App from the contents of a google-services.json file passed as a string, and returns a handle to it. It is firebase_app_initialize_with_options with the options parsed for you: the same rules apply to the name (empty for the default app, anything else for a second app) and to the handle.

If the string is not a Firebase configuration the function returns 0 and firebase_last_error_code is FirebaseError.InvalidArgument; if the SDK then cannot create the app it is FirebaseError.NotInitialized.


Syntax:

firebase_app_initialize_from_json(json_config, name)
Argument Type Description
json_config String The contents of a google-services.json file.
name String The name for the app, or an empty string to create the default app.


Returns:

Real

A handle to the new app, or 0 when it could not be created.


Example:

var _buffer = buffer_load("second-project.json");
var _json = buffer_read(_buffer, buffer_text);
buffer_delete(_buffer);

second_app = firebase_app_initialize_from_json(_json, "second");
The above code loads a configuration file from the Included Files with buffer_load, reads it as text and creates a named app from it. Keep such a file out of a public repository: it identifies your Firebase project.

firebase_app_handle_get_options(app)

firebase_app_get_default_options¶

Firebase C++ SDK: firebase::App::options

This function returns the FirebaseAppOptions of the default app - the values read from google-services.json or GoogleService-Info.plist. Every variable of the struct is present; a setting the file did not supply is an empty string.


Syntax:

firebase_app_get_default_options()

FirebaseAppOptions

The default app's settings, or undefined when the default app does not exist.

The above code prints the project ID and the storage bucket of the default app, which is a quick way to check that the right configuration file made it into the build.

firebase_app_release_handle¶

This function releases an app handle returned by firebase_app_get_default_handle, firebase_app_get_instance, firebase_app_get_apps, firebase_app_initialize_with_options or firebase_app_initialize_from_json. Only the handle goes: the Firebase App itself is never destroyed, and a new handle to it can be fetched at any time. Releasing a handle that was already released, or 0, does nothing.


Syntax:

firebase_app_release_handle(app)
Argument Type Description
app Real The app handle to release.


Returns:

N/A


Example:

var _app = firebase_app_get_default_handle();
firebase_messaging_initialize_for_app(_app);
firebase_app_release_handle(_app);
The above code uses a handle for a single call and releases it straight after. The messaging module keeps its own reference to the app, so the handle is not needed once the call has returned.

firebase_set_log_level¶

Firebase C++ SDK: firebase::SetLogLevel

This function sets how much the Firebase SDK logs: every message at or above the given level is written to the platform's log (logcat on Android, the system log on iOS, standard output on desktop). The default is FirebaseLogLevel.Info. The setting is global - it applies to every app and every product.

A value that is not a FirebaseLogLevel member is refused: the level is left unchanged and firebase_last_error_code is FirebaseError.InvalidArgument.


Syntax:

firebase_set_log_level(level)
Argument Type Description
level FirebaseLogLevel The lowest level to log.


Returns:

N/A


Example:

if (debug_mode)
{
    firebase_set_log_level(FirebaseLogLevel.Verbose);
}
The above code turns on the SDK's full logging while the game runs from the IDE, which is where the SDK's own messages about a missing configuration or a rejected request are most useful.

firebase_get_log_level¶

Firebase C++ SDK: firebase::GetLogLevel

This function returns the SDK's current log level, as set with firebase_set_log_level.


Syntax:

firebase_get_log_level()

FirebaseLogLevel

The lowest level the SDK currently logs.

if (firebase_get_log_level() > FirebaseLogLevel.Debug)

The above code lowers the log level to Debug unless it is already at Debug or Verbose.

FirebaseError¶

What every asynchronous function of this extension returns. Ok means the call reached the SDK and the callback will be called exactly once with the SDK's own result. Any other value means the call failed before the SDK was involved, the callback will never be called, and firebase_last_error_code and firebase_last_error_message say why.

The failure codes are negative on purpose, so they can never be mistaken for a product's own error code (the SDK's are zero or positive). Ok is 0: compare a return against FirebaseError.Ok, never test it for truth - if (firebase_..._(...)) runs on failure, not on success.

NotInitialized The module the function belongs to has not been initialised, or the default app does not exist.
InvalidArgument An argument was refused before the call - an enum value outside its range, a value of a kind the SDK cannot take, an empty name where one is required.
Unsupported The operation is not available on this platform, or is not implemented by this version of the extension.

FirebaseLogLevel¶

The Firebase SDK's log levels, from the most to the least verbose, for firebase_set_log_level and firebase_get_log_level. Setting a level logs every message at that level and above.

FirebaseAppOptions¶

The settings a Firebase App is created from - the values google-services.json and GoogleService-Info.plist carry. firebase_app_initialize_with_options takes one; a variable left undefined there keeps the SDK's default. firebase_app_get_default_options and firebase_app_handle_get_options return one with every variable present, an empty string standing for a setting that was not supplied.

This struct is referenced by the following functions:

  • firebase_app_initialize_with_options
  • firebase_app_handle_get_options
  • firebase_app_get_default_options


Member Type Description
app_id String The Firebase app ID that identifies this app (mobilesdk_app_id in google-services.json, GOOGLE_APP_ID in the plist).
api_key String The API key that authenticates requests from the app.
messaging_sender_id String The Cloud Messaging sender ID.
database_url String The Realtime Database root URL.
ga_tracking_id String The Google Analytics tracking ID.
storage_bucket String The Cloud Storage bucket name.
project_id String The Google Cloud project ID.
